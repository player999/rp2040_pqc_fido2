# RP2040 Post-Quantum & Classical FIDO2 / WebAuthn Authenticator

Повнофункціональна прошивка апаратного ключа безпеки **FIDO2 / CTAP2.1 (WebAuthn)** для мікроконтролера **Raspberry Pi RP2040** (орієнтована на компактний USB-A донгл [Waveshare RP2040-One](https://www.waveshare.com/wiki/RP2040-One)).

Проєкт реалізує повноцінну підтримку **постквантової криптографії (PQC)** відповідно до новітніх фінальних стандартів NIST (FIPS 204 та FIPS 203) поруч із класичною криптографією максимальної криптостійкості (NIST P-521 / ES512 та P-256 / ES256).

## 1. Ключові особливості

* **Постквантовий підпис (FIPS 204)**: реалізація **ML-DSA-87** (Dilithium-5) для створення облікових даних (`MakeCredential`) та генерації тверджень автентифікації (`GetAssertion`).
* **Постквантовий обмін ключами (FIPS 203)**: реалізація **ML-KEM-1024** (Kyber-1024) для узгодження сесійних ключів у CTAP2.1 `pinUvAuthProtocol` 3.
* **Повна сумісність зі стандартами IANA та RFC 9964**: передача параметрів публічних ключів PQC за офіційним стандартом `COSEKey` (AKP, `kty: 7`, `alg: -50`, `PUB = -1`), що забезпечує «з коробки» роботу з актуальними веб-серверами (зокрема `webauthn.io` / `py_webauthn`).
* **Апаратний розгін RP2040 до 200 МГц**: прискорення обчислення поліноміальної математики liboqs більш ніж у **3.3 рази** (час формування підпису ML-DSA-87 знижено з 7.4 с до **~2.2 с**).
* **Нескінченна кількість акаунтів (Stateless Key Wrapping)**: приватні ключі не займають Flash-пам'ять ключа, а шифруються апаратним Master Key (AES-256-CBC + HMAC-SHA256) і зберігаються на боці веб-сайтів.
* **Фізичне підтвердження присутності (User Presence)**: високошвидкісне опитування кнопки BOOTSEL (500 Гц / 2 мс) безпосередньо з шини QSPI Flash без конфліктів із XIP.
* **Запобігання таймаутам браузера (CTAPHID Keepalive)**: автоматична відправка пакетів `CTAPHID_CMD_KEEPALIVE` зі статусом `STATUS_UPNEEDED` кожні 100 мс.
* **Анімація стану на апаратному перериванні**: WS2812 LED плавно анімується таймером на 33 Гц і не зависає навіть під час найінтенсивніших математичних обчислень liboqs.
* **USB Composite Device**: робота одночасно як FIDO2 CTAPHID (інтерфейс 0) та USB CDC Serial Console (інтерфейси 1 і 2) для діагностики та керування.

## 2. Апаратна платформа: Waveshare RP2040-One

Прошивка оптимізована під мініатюрний форм-фактор USB-A донгла **Waveshare RP2040-One**:
* **MCU**: Raspberry Pi RP2040 (двоядерний ARM Cortex-M0+ @ 200 МГц).
* **Flash**: 4 МБ Quad-SPI NOR Flash (Winbond).
* **Кнопки**: 
  - `BOOT` (BOOTSEL) — підключена до лінії `QSPI_CS` через підтягуючий резистор 10 кОм. Використовується як тактильна кнопка підтвердження присутності користувача (User Presence) та для екстреного перезавантаження в bootloader при утриманні > 2 с.
  - `RESET` — апаратне скидання мікроконтролера.
* **Світлодіод**: вбудований адресний SMD LED WS2812B (2020) на контакті **GPIO 16** (порядок байтів кольору: **RGB**).
* **Форм-фактор**: монолітна плата з готовим роз'ємом USB Type-A для прямого підключення до ПК.

## 3. Криптографічна архітектура та алгоритми

Ключ підтримує повний спектр алгоритмів FIDO2: від експериментальних постквантових до найпотужніших еліптичних кривих.

| Клас | Алгоритм | Стандарт | COSE ID | `kty` | Призначення | Час виконання (@200 МГц) |
|---|---|---|---|---|---|---|
| **PQC** | **ML-DSA-87** (Dilithium-5) | FIPS 204 / RFC 9964 | `-50` | `7` (AKP) | Підпис реєстрації та авторизації | **2.20 с** (assert) / 4.40 с (keygen) |
| **PQC** | **ML-DSA-87** (Compat) | SandboxAQ draft | `-20` | `5` (LWE) | Зворотна сумісність із ранніми чернетками | **2.20 с** |
| **PQC** | **ML-KEM-1024** (Kyber-1024) | FIPS 203 | `-24` | `4` (KEM) | CTAP2.1 PIN/UV обмін ключами (Protocol 3) | **0.28 с** |
| **ECC** | **ECDSA secp521r1** (P-521) | FIPS 186-4 | `-36` (ES512) | `2` (EC2) | Класичний підпис максимальної криптостійкості | 2.70 с (assert) / 5.20 с (keygen) |
| **ECC** | **ECDH secp521r1** (P-521) | NIST SP 800-56A | `-25`, `-29` | `2` (EC2) | Класичний обмін ключами ClientPIN | 0.15 с |
| **ECC** | **ECDSA secp256r1** (P-256) | FIPS 186-4 | `-7` (ES256) | `2` (EC2) | Повна сумісність зі стандартними браузерами | **0.05 с** |

### Детерміністичний вивід ключів PQC (`keypair_internal`)
Стандартний генератор пар ключів ML-DSA використовує випадкові байти для створення приватного ключа розміром 4896 байтів. Оскільки зберігати такий ключ у зашифрованому заголовку облікових даних неможливо, у прошивці реалізовано детерміністичний вивід пари ключів із 32-байтного випадкового сіду (`cred_seed`):
```c
// Виклик внутрішньої детерміністичної генерації FIPS 204:
PQCP_MLDSA_NATIVE_MLDSA87_C_keypair_internal(pk, sk, cred_seed);
```
Завдяки цьому під час входу на сайт (`GetAssertion`) приватний ключ розраховується математично на льоту зі збереженого зашифрованого сіду й ідеально відповідає публічному ключу, зареєстрованому на сервері.

## 4. Зберігання облікових даних (Key Wrapping & Passkeys)

### Безлімітне зберігання через Key Wrapping (Non-discoverable Credentials)
Для звичайних облікових даних (як за замовчуванням на `webauthn.io`) використовується технологія **Key Wrapping**:
1. Під час реєстрації (`MakeCredential`) генерується випадковий 32-байтний `cred_seed`.
2. Структура `[алгоритм (2B)] + [довжина (2B)] + [cred_seed (32B)] + [rp_id_hash (32B)]` шифрується алгоритмом **AES-256-CBC** та підписується **HMAC-SHA256**.
3. Для шифрування використовується **Master Key**, який апаратно формується з унікального заводського ідентифікатора чіпа RP2040 ([`pico_get_unique_board_id()`](file:///home/player999/Work/fido2/rp2040_fido2_pqc/src/storage.c#L23-L32)):
   $$\text{MasterKey} = \text{SHA-256}(\text{BoardUniqueID} \parallel \text{SALT})$$
4. Зашифрований блок (144 байти) повертається браузеру як `credentialId` і зберігається в базі даних сервера Relying Party.
5. Під час автентифікації (`GetAssertion`) сайт надсилає `credentialId` назад. RP2040 розшифровує його, перевіряє HMAC і звіряє `rp_id_hash` (захист від фішингу).

*Переваги:*
* Можливість реєстрації на **необмеженій кількості сайтів** (Flash-пам'ять ключа не заповнюється).
* Фізична прив'язка: розшифрувати `credentialId` може **виключно цей конкретний мікроконтролер**.

### Резидентні ключі (Discoverable Credentials / Passkeys)
Для сайтів, що вимагають вхід без логіна (Usernameless flow / Autofill Passkeys), у коді [src/storage.c](file:///home/player999/Work/fido2/rp2040_fido2_pqc/src/storage.c) передбачено сховище `ResidentCredential` на 8 облікових записів.

## 5. Апаратне підтвердження присутності (User Presence)

Для захисту від несанкціонованого віддаленого доступу та шкідливого ПЗ кожна операція створення або використання облікових даних вимагає фізичного дотику до кнопки:

* **Безпечне опитування кнопки BOOTSEL**: лінія `QSPI_CS` опитується спеціальною функцією в RAM ([`user_presence_is_button_pressed`](file:///home/player999/Work/fido2/rp2040_fido2_pqc/src/user_presence.c#L16-L30)), яка короткочасно переводить пін у High-Z стан з вимкненими перериваннями, читає `sio_hw->gpio_hi_in` і миттєво повертає пін у режим роботи XIP.
* **Опитування на частоті 500 Гц**: стан кнопки перевіряється кожні **2 мс**, що гарантує 100% реєстрацію навіть найшвидшого короткого дотику пальцем (від 10 мс).
* **CTAPHID Keepalive**: кожні 100 мс під час очікування дотику пристрій надсилає пакет `CTAPHID_CMD_KEEPALIVE` (`STATUS_UPNEEDED`). Завдяки цьому браузер тримає вікно підтвердження активним до 30 секунд і не відключає USB-інтерфейс по таймауту.
* **Ізоляція тестового автопідтвердження**: код автоматичного підтвердження повністю вимкнено з компіляції за допомогою макроса `#ifdef ENABLE_AUTO_CONFIRM`. У робочій прошивці діє **виключно фізичне натискання кнопки**.

## 6. Апаратна світлодіодна індикація (WS2812 RGB)

Світлодіод WS2812 (GPIO 16) управляється окремим автоматом станів на апаратному таймері RP2040 (частота оновлення **33.3 Гц / 30 мс** через PIO). Анімація працює незалежно від обчислювального навантаження CPU.

| Режим | Колір | Поведінка світлодіода | Значення для користувача |
|---|---|---|---|
| **IDLE** | 🔵 **Сапфірово-синій** | Плавне спокійне пульсування (`0, 0, 8..38`) | Ключ увімкнений, готовий до роботи |
| **UP_REQUIRED** | 🟡 **Золотисто-жовтий** | Швидке миготіння (4 Гц, `220, 180, 0`) | **Очікується дотик!** Натисніть кнопку BOOTSEL |
| **PQC_ACTIVE** | 🟣 **Неонова Маджента / Фіолетовий** | Хвилеподібне «дихання» (`70..255, 0, 100..255`) | **Триває постквантове обчислення** (~2.2 с). Зачекайте |
| **SUCCESS** | 🟢 **Смарагдово-зелений** | Світить 750 мс, плавно згасає 300 мс | Операцію успішно виконано! |
| **ERROR** | 🔴 **Рубіново-червоний** | Яскравий спалах 750 мс з плавним згасанням | Помилка або таймаут очікування дотику |
| **BOOTLOADER**| 🟠 **Бурштиновий** | Постійне рівне світіння (`255, 120, 0`) | Пристрій переведено в режим прошивки (BOOTSEL) |

> [!NOTE]
> Світлодіод на платах Waveshare RP2040-One має апаратний порядок колірних каналів **RGB** (на відміну від класичного GRB). Прошивка автоматично враховує цю інверсію.

## 7. Режими перезавантаження в BOOTSEL та прошивка

Для зручності розробки ключ можна перевести в режим оновлення прошивки (USB Mass Storage `RPI-RP2`) **без відключення кабелю USB**:

1. **Автоматична прошивка однією командою**:
   ```bash
   bash scripts/flash.sh
   ```
   Скрипт сам збирає свіжий двійковий файл, посилає сигнал перезавантаження, очікує монтування розділу `RPI-RP2` та копіює `rp2040_fido2_pqc.uf2`.
2. **Апаратна кнопка BOOTSEL**:
   Затисніть кнопку **BOOT** на платі довше ніж на **2 секунди**. Світлодіод засвітиться помаранчевим, і плата перезавантажиться в BOOTSEL.
3. **USB CDC 1200 bps Touch**:
   ```bash
   stty -F /dev/ttyACM0 1200
   ```
4. **Команда консолі**:
   У терміналі порту `/dev/ttyACM0` натисніть клавішу `b`.
5. **Вендорна команда CTAPHID**:
   ```bash
   bash scripts/reboot_bootsel.sh
   ```

## 8. Збірка та встановлення

### Вимоги:
* GNU Arm Embedded Toolchain (`arm-none-eabi-gcc` 10+ / 13+)
* Raspberry Pi Pico SDK (1.5.0+)
* CMake (3.13+) та Make
* Встановлена бібліотека `liboqs` (включена у підкаталог або сусідню папку)

### Кроки збірки:
```bash
# 1. Налаштування змінних оточення
export PICO_SDK_PATH=/шлях/до/pico-sdk
export PATH=/шлях/до/toolchain/bin:$PATH

# 2. Створення каталогу збірки
cd rp2040_fido2_pqc
mkdir -p build && cd build

# 3. Конфігурація CMake (оптимізація за розміром та швидкістю)
cmake -DCMAKE_BUILD_TYPE=MinSizeRel ..

# 4. Компіляція
make -j$(nproc)
```
Результатом збірки є файл `build/rp2040_fido2_pqc.uf2`.

### Швидке прошивання:
Підключіть Waveshare RP2040-One до USB, утримуючи кнопку BOOT (або якщо пристрій уже запущений — запустіть скрипт):
```bash
bash scripts/flash.sh
```

## 9. Тестування та сумісність з WebAuthn

### Тестування у реальному браузері (webauthn.io):
1. Відкрийте браузер (Google Chrome, Chromium, Firefox) і перейдіть на [https://webauthn.io/](https://webauthn.io/).
2. Введіть ім'я користувача.
3. У списку **Algorithm** оберіть:
   - **ML-DSA 87** (для перевірки постквантового алгоритму FIPS 204);
   - або **ES512** / **ES256** (для перевірки класичних еліптичних кривих).
4. Натисніть **Register**:
   - Ключ почне швидко блимати жовтим світлом (очікування User Presence).
   - Натисніть кнопку **BOOT** на ключі.
   - Світлодіод почне «дихати» неоновою маджентою (~2.2 с, генерація пари ключів та підпис атестації).
   - Світлодіод спалахне зеленим — браузер повідомить: *"Success! Now try to authenticate..."*.
5. Натисніть **Authenticate**:
   - Ключ знову заблимає жовтим — натисніть кнопку **BOOT**.
   - Після короткого пульсування маджентою ключ підтвердить підпис зеленим світлом, і вхід буде успішно підтверджено!
