# RP2040 Post-Quantum & Classical FIDO2 Authenticator

Повнофункціональна прошивка FIDO2 / CTAP2.1 ключа безпеки для мікроконтролера **Raspberry Pi RP2040** (платформа [Waveshare RP2040-One](https://www.waveshare.com/wiki/RP2040-One)), оптимізована для одночасного використання пост-квантової та класичної криптографії найвищого рівня стійкості.

---

## 1. Підтримувані алгоритми

| Тип | Алгоритм | Стандарт | COSE ID | Призначення | Час виконання на RP2040 |
|---|---|---|---|---|---|
| **PQC** | **ML-DSA-87** (Dilithium-5) | FIPS 204 / RFC 9964 | `-50`, `-20` | Підпис атестації та асерцій | 4.54 с (keygen+attest) / 3.04 с (assert) |
| **PQC** | **ML-KEM-1024** (Kyber-1024) | FIPS 203 | `-24` (KEM) | Обмін ключами ClientPIN (Protocol 3) | 0.39 с |
| **ECC** | **ECDSA secp521r1** (P-521) | FIPS 186-4 | `-36` (ES512) | Класичний підпис максимальної стійкості | 5.30 с (keygen) / 2.70 с (assert) |
| **ECC** | **ECDH secp521r1** (P-521) | NIST SP 800-56A | `-25`, `-29` | Класичний обмін ключами ClientPIN | ~0.15 с |
| **ECC** | **ECDSA secp256r1** (P-256) | WebAuthn Compat | `-7` (ES256) | Сумісність зі стандартними браузерами | 0.08 с |

## 2. Автоматичне повернення в режим програмування (BOOTSEL)

Для повернення донгла в режим програмування без відключення від USB або фізичного натискання кнопок реалізовано 4 незалежних методи:

### Спосіб 1: Скрипт або CTAPHID-команда (найшвидший і 100% надійний)
```bash
./scripts/reboot_bootsel.sh
```
Цей скрипт надсилає вендорний пакет CTAPHID (`0xD1`) на `/dev/hidraw*`. Пристрій миттєво перезавантажується у вбудований ROM USB Bootloader, і в системі з'являється диск `/media/$USER/RPI-RP2`.

### Спосіб 2: Автоматична перепрошивка в одну команду
```bash
./scripts/flash.sh
```
Скрипт сам перевіряє поточний стан: якщо ключ працює в режимі FIDO2, скрипт відправляє сигнал перезавантаження, чекає монтування `RPI-RP2`, копіює `rp2040_fido2_pqc.uf2` і запускає оновлену прошивку.

### Спосіб 3: USB CDC (1200 baud touch)
```bash
stty -F /dev/ttyACM0 1200
```
Скидання за стандартом Arduino / Pico: перемикання порту на швидкість 1200 bps автоматично переводить пристрій у BOOTSEL.

### Спосіб 4: Консольна команда або фізична кнопка
- У відкритому терміналі `/dev/ttyACM0` введіть клавішу `b` (reboot).
- Або затисніть фізичну кнопку BOOTSEL на платі довше ніж на **2 секунди**.

## 3. Збірка та тестування

### Збірка:
```bash
export PICO_SDK_PATH=/home/player999/Work/pico-sdk
export PATH=/home/player999/Work/toolchain/bin:$PATH
mkdir -p build && cd build
cmake -DCMAKE_BUILD_TYPE=MinSizeRel ..
make -j$(nproc)
```

### Тестування веб-сумісності (WebAuthn / Браузери):
```bash
./scripts/test_webauthn_site.py
```
Використовує системний рушій `libfido2` (той самий, що вбудований у Firefox, Google Chrome та Chromium) для симуляції повної реєстрації та авторизації на сайтах (профіль `webauthn.io`). Авто-підтвердження (Auto-UP) увімкнене за замовчуванням — при запиті сайтів ключ робить короткий імпульс жовтим LED і автоматично підтверджує присутність без потреби вручну натискати кнопку!

### Повний запуск діагностики всіх алгоритмів:
```bash
./scripts/test_fido2.py --auto-up
```
Прапорець `--auto-up` тимчасово вмикає автоматичне підтвердження User Presence на пристрої для проходження CI/тестового пайплайну без ручного торкання кнопки. Без цього прапорця донгл блимає жовтим LED і чекає фізичного натискання кнопки BOOTSEL.

## 4. Світлодіодна індикація (WS2812 на GPIO 16)
- **Бірюзовий (Cyan)** — Ключ очікує дій у режимі очікування.
- **Жовтий блимаючий (Blinking Yellow)** — Очікується підтвердження присутності користувача (User Presence touch).
- **Фіолетовий (Magenta)** — Працює пост-квантове обчислення (ML-DSA-87 / ML-KEM-1024).
- **Зелений (Green)** — Операція успішно завершена.
- **Червоний (Red)** — Помилка / таймаут очікування натискання.
- **Синій (Blue)** — Перезавантаження в режим BOOTSEL.
